# クリップボード履歴モジュール 設計メモ

Windows の「クリップボード履歴」(Win+V) に相当する機能を `Modules/Clipboard/` に追加する。
このメモは実装の判断基準であり、方針を変えるときはコードより先にここを更新する。

対象: `Sources/MacToolkit/Modules/Clipboard/`

## 0. 前提と既存方針との関係

- `ToolModule` / `ModuleRegistry` / `Sampler` の枠組みに乗せる。モジュール独自 Timer は作らない
- ユーザーに見える文言は全て日本語、`UI/DesignSystem.swift` の部品経由
- サンドボックス外・ad-hoc 署名の `.app` 配布が前提
- **既存方針との衝突が 1 点ある**（§1）。ARCHITECTURE.md §4 の「イベントで取れるものはポーリングしない」に対し、
  `NSPasteboard` には変更通知の API が存在せずポーリングが唯一の公開手段。同ファイルに例外として追記済み

## 1. 変更検知: changeCount ポーリングを tick() に載せる

**結論: `tick()` で `NSPasteboard.general.changeCount` を比較する。既定 1 秒で初期スコープは十分。**

- macOS には pasteboard 変更の公開通知が無い（Windows の `AddClipboardFormatListener` 相当が無い）。
  既存の OSS も全てポーリングしている。「イベント駆動優先」方針の**正当な例外**であり、
  独自 Timer を作らず既存 Sampler に相乗りすることで「1 プロセス・1 タイマー」の価値は守る
- `changeCount` の読み取りは XPC を伴うが実測 µs オーダーで、`tick()` の 1ms 予算に収まる。
  変化が無ければそれ以外は何もしない
- 変化検出時のデータ読み出しは同じ tick 内で行ってよい（テキスト主体なら軽い）。
  画像の取り込みだけは重くなり得るので、サムネイル生成は `Task.detached` に逃がす（PR3）
- **体感**: コピー直後 0〜1 秒遅れて履歴に載る。「コピー→即 Win+V」の最速操作で最新項目が出遅れることがあるため、
  パネル表示時に 1 回だけ強制チェックを走らせて解消する（タイマー追加ではなくイベント時の追加サンプリング）
- 1 周期内に 2 回コピーした場合の取りこぼしは仕様として許容する

## 2. 対応する型と初期スコープ

| 型 | UTType | スコープ |
|---|---|---|
| プレーンテキスト | `public.utf8-plain-text` | PR1 |
| ファイル URL | `public.file-url` | PR1（パス文字列として扱う） |
| RTF | `public.rtf` | PR3。生データを保持し、一覧はプレーンテキスト化した先頭行 |
| 画像 | `public.png` / `public.tiff` | PR3。サムネイルのみメモリ保持 |

再コピー時に元の全型を復元するため、1 履歴項目 = `[String: Data]`（型 → データ）＋
表示用メタデータ（プレビュー文字列・種別・日時・コピー元アプリ）で持つ。

## 3. 保存方式

**結論: 初期はメモリのみ・上限 50 件。永続化は PR3 で Application Support 配下にファイルベースで。**

- 件数上限 50（設定で 20〜200）。1 項目のデータサイズ上限 1MB
  （超過分はプレビュー文字列のみ保持し「大きすぎるため再コピーできません」と表示）
- 画像はメモリに最大 128px サムネイルのみ。モジュール全体で +5MB 以内を目標にする
- **UserDefaults が不適な理由**:
  1. plist 全体が起動時に一括ロードされ、変更ごとに全書き戻しされる。数 MB を入れるとアプリ全体の defaults が遅くなる
  2. 機密情報が `~/Library/Preferences` に平文で残り `defaults read` で覗ける
  3. 実質的なサイズ上限がある

  履歴データは `~/Library/Application Support/MacToolkit/ClipboardHistory/` に置く
- 永続化する場合も**機密フラグ付き・除外アプリ由来の項目は書かない**。
  既定は「テキストのみ永続化、画像はセッション内のみ」

## 4. UI

**結論: ポップオーバー内 1 セクション（直近数件）＋ Win+V 相当の独立フローティングパネルの両方。**

- セクションは他モジュールと同じ `ModuleSection` に収める。行クリックでクリップボードへ戻す
- 本命の UX はグローバルホットキー（既定 ⌥⌘V）で出す `NSPanel`（`.nonactivatingPanel` + `NSHostingView`）。
  **nonactivating が肝**で、前面アプリのフォーカスを奪わないため後述のペーストが成立する。
  ↑↓ + Return / クリックで選択、Esc で閉じる
- **ホットキーの実装**: 現状リポジトリにホットキー基盤は無いので新規。
  Carbon の `RegisterEventHotKey` を採用する。非推奨扱いだが公開 API で現役、かつ**追加権限が不要**なのが決め手。
  `NSEvent.addGlobalMonitorForEvents` は「入力監視」権限が要るうえキーを消費できないため不採用。
  CGEventTap も同権限が要るため不採用。将来 Screenshot にも付ける前提で `Core/HotKeyCenter.swift` に置く
- ⌘⇧V はエディタのプレーンテキストペーストと衝突するため既定にしない。キーはユーザー変更可能にする

## 5. ペースト

**結論: 初期スコープは「クリップボードに戻すだけ」。自動ペーストは PR4 のオプトイン設定。**

- 自動ペースト（選択→元アプリに ⌘V 送出）は `CGEvent` の keyDown 合成が必要で、**アクセシビリティ権限**を要求する
- リスク: ad-hoc 署名アプリは再ビルドごとに権限が剥がれる／
  セキュア入力フィールド（パスワード欄）では無効化される／IME 変換中の挙動が不安定。よって既定オフ
- 「戻すだけ」でも nonactivating パネルなら「ホットキー→選択→⌘V」の 2 アクションで完結し、体感は十分良い

## 6. プライバシー

- **`org.nspasteboard.ConcealedType` / `TransientType` / `AutoGeneratedType` が付いた項目は記録しない。**
  nspasteboard.org の業界慣行で、1Password 等が付与する。型リストに含まれるかを見るだけなので `tick()` 内で安価
- 除外アプリ: コピー検出時に `NSWorkspace.shared.frontmostApplication` の bundle ID を記録し、
  除外リスト（既定で主要パスワードマネージャを同梱）に一致したら記録しない。
  frontmost はコピー元の近似であり、バックグラウンドコピー（スクリプト等）では外れる点は既知の限界
- 「履歴をすべて消去」をセクションと設定の両方に置く。`stop()`（モジュール無効化）時もメモリ履歴を破棄

## 7. ファイル構成と ToolModule 適合

```
Core/HotKeyCenter.swift          … RegisterEventHotKey ラッパ（共有基盤・PR2）
Modules/Clipboard/
  ClipboardItem.swift            … 履歴 1 件の値型（型辞書・プレビュー・出所・機密判定）
  ClipboardWatcher.swift         … changeCount 比較と項目読み出し（UI 非依存。*Counters 相当）
  ClipboardHistory.swift         … 上限付きの履歴保持（PR3 でディスク永続化）
  ClipboardModule.swift          … ToolModule 準拠。tick() で watcher を叩き history に積む
  ClipboardPanel.swift           … nonactivating NSPanel + SwiftUI リスト（PR2）
```

- 登録は `MacToolkitApp.init` の配列に 1 行追加
- `isAvailable` は常に true（NSPasteboard は全 Mac で使える）。デフォルト実装のまま
- `statusItemView()` は nil（メニューバーに数値を出さない）
- 設定キーは規約どおり `clipboard.maxItems` / `clipboard.excludedBundleIDs` / `clipboard.autoPaste` の名前空間

## 8. 実装ステップ

1. **PR1: テキスト履歴 + ポップオーバーセクション** — Item / Watcher / History / Module。
   ホットキー無し・メモリのみ・テキスト + ファイル URL のみ。
   機密フラグ除外は**この段階から入れる**（後付けだと漏れた履歴が残るため）。
   検証: `swift run` で TextEdit・1Password からコピーし、履歴掲載/除外とメモリ推移を確認
2. **PR2: HotKeyCenter + フローティングパネル** — ⌥⌘V でパネル、キーボード選択、クリップボードへ戻す。
   検証: `./scripts/install.sh` で `/Applications` から起動し、全画面アプリ・別 Space・セキュア入力中の挙動を確認
3. **PR3: RTF/画像対応 + ディスク永続化** — サムネイル生成の `Task.detached` 化、起動時復元。
   検証: 大きな画像コピー時の `tick()` 所要時間（1ms 予算）とフットプリントを計測
4. **PR4: 自動ペースト（オプトイン）** — アクセシビリティ権限フロー。検証は `.app` 必須

## 9. リスク・未確定

- ポーリング以外の検知手段が無い事実は将来の OS でも変わらない見込み
- `RegisterEventHotKey` は legacy API。将来消えたら CGEventTap（入力監視権限が必要）への移行が要る
- ad-hoc 署名では TCC 権限（アクセシビリティ）がビルドごとにリセットされ、PR4 の検証が煩雑
- **1 秒周期の XPC 読み取りがアイドル消費に与える影響は未計測。**
  PR1 で `powermetrics` の前後比較を行い、問題があれば「パネル/ポップオーバーを開いた時だけ高頻度化」等を検討する
- プライベート API は使わない（全て公開 API で成立する）
